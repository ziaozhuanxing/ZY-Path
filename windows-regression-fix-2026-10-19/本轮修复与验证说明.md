# 崩溃原因与修复说明 — 2026-10-19

## Windows 原始记录

19:03 的逐行/Qt 跟踪确认：缺失模型用例单独运行通过；rerun 模块运行到第四个用例创建窗口阶段时，Qt 明确报 `QThread: Destroyed while thread is still running`，随后以 `0xC0000409` 终止。后台栈正在 ModelValidationThread.run → torch.load；此时还未点击“缺失模型”的 Re-run，不能把 pathlib 内部正常捕获的 AttributeError 当作崩溃原因。Windows Application Error 查询没有匹配事件，Qt 致命消息与线程栈是本次直接证据。

关闭操作会被主窗口 closeEvent 在有后台工作时推迟，但 pytest-qt 的清理代码在 close() 后继续调用 deleteLater()。当父窗口被强制销毁，仍运行的子 QThread 会触发 Qt 的致命退出。增加父对象 destroyed 的 DirectConnection 保护，在 Qt 删除子线程前等待 run 结束；已有普通关闭异步行为保留。设置中的模型验证也使用该线程类。

历史序列实际结果是 96 passed / 1 failed / 0 errors；它不是完整测试。跟踪显示同一坐标 (359,77) 在按下/释放时位于第二行，双击时已成为空白位置（row=-1,column=-1）。两次事件之间执行了延迟列宽函数，其中包含 resizeRowsToContents。将行高计算放到显示记录时同步完成，字体/主题变化时仍更新，延迟列宽计算不再改变行高。
